# 作品分发、班级与收件箱接入说明

本阶段完成作品审核后的真实分发链路。数据库迁移为 `0015_publication_distribution`；Android 将“书信”接为家长/班级作品收件箱与班级管理入口，并在封卷发布时提供真实班级选择。公开作品继续进入大会知行流。分发本身不使用智能 Agent。

## 1. 可执行链路

1. 成人账户调用 `POST /v1/classrooms` 创建班级；响应返回一次性展示的 8 位邀请码，数据库只保存哈希。
2. 学习者在“书信”页输入邀请码并调用 `POST /v1/classrooms:join`。重复加入保持幂等，班级创建者不能加入自己的班级。
3. `GET /v1/me/classrooms` 返回本人创建或已加入的有效班级，不再返回邀请码。只有 `role=MEMBER` 的班级可作为作品投递目标。
4. 封卷页选择 `CLASSROOM` 时必须再选择一个可投递班级，并把 `target_classroom_id` 随 `POST /v1/creation-projects/{project_id}/submissions` 提交。服务端再次核验有效成员关系。
5. `GUARDIAN_ONLY`、`CLASSROOM`、`COMMUNITY` 都先进入原有审核状态机；提交成功不代表已分发。
6. 审核结论为发布时，在同一事务中创建或激活收件人快照。班级作品投递给班级创建者，家长作品投递给已验证监护关系对应的成人账户。
7. `GET /v1/me/publication-inbox` 返回当前用户收到且仍有效的家长/班级作品；`GET /v1/community/feed` 返回仍在发布中的知行流作品。
8. 作者撤回作品或审核发布结论被撤销时，已有投递改为 `REVOKED`，收件箱和知行流立即不再展示该作品。

## 2. Android 页面与按键

- 首页“书信”：进入作品来信页，同时加载收件箱与班级列表。
- 顶部返回：返回上一页；刷新：重新请求收件箱与班级，加载期间禁用以防重复操作。
- 未成年/学习者账户：显示“加入班级”、8 位邀请码输入框和“确认加入”。输入会移除空格与连字符并统一为大写。
- 成人账户：显示“我创建的班级”、班级名称输入框和“创建班级”。创建成功后仅在当前状态显示一次邀请码，用户关闭后不能从列表重新读取。
- 班级列表：展示名称、创建者、角色和有效成员数；服务端返回 `can_submit` 作为发布页是否可选的唯一依据。
- 最新作品：首屏最多 20 条；有游标时显示“查看更多”。空、加载、失败都有独立状态，失败可重试。
- 封卷“教师/班级可见”：展示 `can_submit=true` 的班级选择项；未选择班级时不能确认提交。没有可选班级时，引导用户先去“书信”加入。
- 大会入口：进入现有演武场/知行流页面；公开作品详情、评招、收藏与改造授权沿用大会模块，不重复建设第二套社区页面。

## 3. 接口与权限

- `POST /v1/classrooms`：仅 `ADULT`；创建班级并返回一次性 `join_code`。
- `POST /v1/classrooms:join`：已登录用户；按邀请码建立或恢复成员关系。
- `GET /v1/me/classrooms`：只返回本人相关的有效班级和成员数，不返回邀请码哈希或明文。
- `GET /v1/me/publication-inbox?cursor=&limit=20`：只返回投递给当前家长或当前用户所创建班级的已发布作品。
- `GET /v1/community/feed?cursor=&limit=20`：只返回 `COMMUNITY + PUBLISHED` 的活动作品，并应用双向黑名单过滤。

列表使用发布时间与作品 ID 组成的不透明游标，`limit` 范围为 1–30。预览地址为短期签名地址；公共响应不包含手机号、内部监护关系或邀请码。社区学习卡是否展示继续受作者隐私设置控制。

## 4. 数据与一致性

- `classrooms`：班级创建者、名称、邀请码哈希和状态。
- `classroom_memberships`：学生与班级的活动成员关系；唯一约束防止重复加入。
- `publication_deliveries`：作品、投递通道、收件人/班级快照、投递和撤销时间。
- `publications.classroom_id`：班级发布的明确目标；非班级发布必须为空。

投递创建与审核发布共享事务，撤回与投递撤销也共享事务，因此不会出现作品已撤回但收件箱仍可见的中间状态。服务端读取时还会再次限定作品、项目、作者和投递均为有效状态。

## 5. Agent 边界

该模块是确定性的权限、审核状态和数据分发，不需要自主 Agent，也不调用大模型。邀请码、成员资格、收件人解析、黑名单和可见范围必须由服务端规则执行。未来若增加“教师评语建议”之类模型能力，也只能作为用户明确触发、可编辑的辅助工具，不能自动加入班级、改变发布范围、代表教师评价或跳过审核。

## 6. 验证要求

- 后端测试覆盖成人创建班级、邀请码不回显、成员加入、班级投递隔离、已验证家长投递、社区发布、黑名单与撤回撤销。
- Android 至少执行 `:app:compileDebugKotlin` 和 `:app:assembleDebug`。
- Docker 环境执行迁移到 `head`，检查 `/healthz`，再用模拟器完成冷启动、进入“书信”、空态/加载态与刷新操作。
