# 机巧江湖大会页后端写入检查与优化报告

检查日期：2026-09-07
需求依据：`D:/shuqi/multimedia/文档/机巧江湖_大会页策划书.docx`
检查范围：大会作品流、评招、收藏、同门改造、匿名切磋、评审、举报、书信、审计与账号数据导出。

## 一、结论摘要

大会页后端已经从“接口预留”推进到可运行的业务闭环：公开作品只读取审核通过且社区可见的不可变版本；所有用户输入都有权限、隐私和并发保护；同门改造保留来源授权快照；匿名切磋具备题目快照、作答、异步评审、结果、自评/互评/师评和复盘；评语与切磋举报都有内部审核入口；关键写入会生成审计事件。

本轮检查发现并修复了两个关键断点：

1. 原“采纳评语”只有状态，没有证明建议落实在哪个作品版本。现在只有已采纳的 `SUGGESTION` 评语才能关联同一作品中晚于参会版本的新版本，并保存改进说明、采纳时间、乐观锁版本、审计和通知。
2. 原切磋举报只有创建记录和结束对局，没有后台查询、确认/驳回与结案通知。现在支持按状态拉取、审核决定、审核引用、结案摘要、并发控制、审计和举报者书信。

账号导出也已经包含大会活动，但不会导出匿名切磋对手的用户 ID。迁移版本为 `0021_conference_feedback_closure`，已验证可降级到 `0020` 并重新升级；全量自动化测试为 93 项全部通过，代码覆盖率 85.17%，Alembic 检查无结构漂移。

当前判断：功能写入链路已具备联调和小规模灰度条件，但生产上线前仍需完成“审核身份与权限、真实账号删除处理器、限流反滥用、容量与可观测性”四类治理工作。

## 二、当前写入链路检查

### 1. 作品流与详情

- 写入来源是审核通过的作品发布记录，展示读取不可变 `creation_version_id`，不会因作者继续编辑而悄悄改变参会作品。
- 社区流固定每页最多 5 件，支持游标；撤回、限制、非社区可见和双方拉黑均会从读取结果排除。
- 返回关联秘籍、学习卡公开摘要、来源与人机分工摘要、AIGC 声明和版本号；不公开完整来源地址和私密学习内容。

评价：写入边界清晰。后续应补作品流曝光/点击/停留等独立分析事件，不要反向修改作品事实表。

### 2. 评招、采纳与收藏

- 结构化模板、同作品同用户同模板唯一约束、自评禁止、公开文本隐私检查均已实现。
- 作者处理使用 `row_version` 防止旧页面覆盖新决定。
- 评语举报可由内部接口移除或保留，被移除内容不再公开展示。
- 新增采纳证据链：`评语 → 参会发布版本 → 同项目后续版本`，保证“采纳”不是孤立标签。
- 收藏写入幂等；作品失效后不再展示收藏内容。

评价：核心闭环完整。建议下一阶段增加作者撤销错误采纳的受控流程，但必须保留原审计记录，不能直接覆盖历史。

### 3. 同门改造

- 申请、作者批准/拒绝、授权快照、撤权和衍生项目关联均已持久化。
- 授权固定源发布与源作品版本，避免源作者后续编辑导致授权范围漂移。
- 源作品撤回或下架会使授权失效，新衍生作品不能继续引用失效授权。

评价：证据链合理。建议增加授权条款版本和用户可读授权文本的长期归档；当前 `authorization_version` 只能标识规则版本，尚不足以独立还原当时完整条款。

### 4. 匿名切磋与评审

- 只按同秘籍页、同年龄段匹配，并排除拉黑关系；排队记录 5 分钟过期。
- 对局固化 3 道题，覆盖核心概念、公案分析、迁移应用；每题答案不可覆盖，同内容重试幂等。
- 双方完成后在同一事务写入 Outbox 判题任务；Worker 支持租约回收、重试和指数退避。
- 生产可调用 HTTPS 评审网关；请求仅使用参与者 A/B 别名，不发送用户 ID、昵称或手机号。
- 结果、自评、互评、师评和复盘均有独立记录与唯一约束。
- 新增举报后台闭环；首次举报结束对局，审核员可确认或驳回并给举报者发送结案书信。

评价：学习闭环已形成。当前确认举报只完成案件结案，不会自动封禁或扣分，这是安全的默认边界；若未来增加处罚，必须另建可申诉的纪律状态机，不能把举报成立直接等同于封号。

### 5. 书信、审计与数据权利

- 评语、改造、匹配、评审、评价、采纳与举报结案会写入站内书信；关闭消息设置后不创建新书信。
- 关键动作写入领域审计，差异仅保存必要 ID、状态和审核引用，不复制评语、答案、举报详情或凭证。
- `/v1/account/export` 已纳入大会评语、采纳、收藏、改造、切磋、作答、评价、复盘、举报和书信。
- 导出采用本人视角，不包含切磋对手用户 ID；收到的评语也不输出评语作者 ID。

评价：导出覆盖已补齐。账号注销已接入 outbox Worker：处理器会撤销会话、使访问令牌失效、清理头像和班级信息、替换手机号密文与昵称并将账号置为 `DELETED`。大会对局、授权凭据和审计证据的保留期限及法定依据仍需上线前由产品与法务确认，因此当前只能宣称“已完成可重复执行的匿名化处理”，不能宣称所有历史数据已物理删除。

## 四、上线前优化建议

### P0：必须完成

1. 将内部共享令牌升级为服务身份或后台 RBAC。当前内部路由使用统一 `X-Internal-Token`，虽然外部不可见，但不能细分“审核员、教学服务、判题 Worker”的最小权限，也不利于人员级追责。
2. 明确大会对局、授权凭据、审计证据的保留期限与法定保留依据，并补充策略化清理任务；当前匿名化处理器已落地，但仍需完成保留策略的产品与法务验收。
3. 增加用户级、IP 级和对象级限流。重点保护评语、举报、匹配入队、作答和书信列表，防止刷屏、举报轰炸和排队占位。
4. 上线真实评审网关前完成模型版本冻结、超时/熔断、人工兜底、偏差抽检和未成年人内容评估；开发规则评分不能用于生产裁定。

### P1：灰度期完成

1. 为举报增加证据最小快照。当前举报详情存在，但没有固化被举报内容当时的安全摘要；内容后来被隐藏时，审核复盘的证据可读性不足。
2. 为举报处罚建立独立、可申诉的状态机。当前只结案不处罚，后续若增加限制匹配或账号处分，应与案件结论解耦。
3. 将大账号导出改为异步文件任务。当前同步导出包含多个领域查询，小数据可用，但大量作品、对局和书信会增加接口延迟与内存占用。
4. 优化大会导出和作品聚合查询，增加批量预取与分页，避免数据量增长后的多次往返。

### P2：持续优化

1. 建立指标：匹配等待 P50/P95、判题积压与失败率、举报待处理时长、评语采纳率、采纳到新版本耗时、授权撤回率。
2. 增加数据保留任务：过期排队记录、长期已读书信、已结案举报详情按策略归档或最小化。
3. 增加运营配置：匹配 TTL、每日举报/评语上限、审核 SLA、评审器版本灰度比例，不应依赖发版调整。
4. 对采纳链做产品展示：在原评语旁明确显示“已用于 Vn”，并允许查看改进摘要，强化策划书要求的“评招促进迭代”。

## 五、建议验收口径

- 评语采纳必须能追溯到同一作品的后续版本；旧版本、其他项目版本和未采纳评语全部拒绝。
- 同一采纳请求网络重试不得重复写信或重复审计；不同版本的二次关联必须冲突。
- 切磋举报创建后对局立即结束，待处理列表可见；只有一次结案成功，旧 `row_version` 和重复结案均失败。
- 对外接口始终不返回对手用户 ID、手机号、昵称、班级或监护信息。
- 判题 Worker 中断后任务可被重新领取，超过最大重试后可观测且可人工补判。
- 大会所有关键写入均可在审计事件中找到，但审计内容不含原文和凭证。
- 账号导出包含本人的大会数据；账号删除申请必须能看到状态，在处理器上线前不得向用户承诺即时物理删除。

## 七、Android 跨页联动落实（2026-09-07）

本阶段已把大会后端的核心能力接入 Android 主流程，不再只停留在接口可用：

- 大会作品页每次进入主动刷新；作品发布成功后使大会缓存失效，避免非空旧列表长期不更新。
- 作品详情补齐版本号、关联秘籍、公开学习卡和人机分工摘要展示。
- 评语补齐“建议”类型、作者处理、采纳到后续作品版本、采纳摘要展示和举报入口。
- 授权批准后可带授权 ID 进入工坊创建衍生作品；返回或主动取消时清理授权来源，防止误带入下一次创作。
- 匿名切磋补齐自动轮询、问题读取、逐题作答、双方进度、等待评审、结果、自评、互评、复盘、举报和重新开局。
- 大会书信建立独立入口；后端读取历史或新书信时统一解析稳定的 `navigation_target/navigation_id`，评语可直达具体作品，切磋可直达具体对局，授权进入授权记录，同时保留旧的作品/班级收件箱入口。
- Android 独立读取 `/v1/meta/capabilities` 控制大会入口；开关关闭时大会入口禁用，书信入口自动回退旧收件箱。能力开关加载不占用大会业务请求的 loading 状态。
- 首页、修炼、行囊和设置页进入时同步大会书信未读数；顶部书信封蜡只在确有未读时显示，读信后即时消除。
- 针对 Docker/模拟器环境中空闲 HTTP 连接偶发失效的问题，客户端只对安全的 GET 请求进行一次新连接重试；评语、作答、举报等写入请求不会被自动重放。
- 登录账号变化时清空大会页和衍生授权状态，避免上一账号的收藏、申请、书信或对局在新账号界面短暂残留。
- Android 编译和单元测试通过；当前为 5 tests、0 failures，覆盖能力开关、大会作品证据字段解析、切磋/书信深链字段解析和对局路由参数。后端全量测试仍为 93 passed。
- 调试 APK 已安装到 Pixel 6 API 34 模拟器；冷启动正常，能力开关、演武场空状态、大会书信未读数和匿名切磋秘籍列表均已连接本地真实 API 验证，未出现崩溃。联调过程中发现并修复了 GET 空闲连接失效问题。

尚待真实环境联调的边界：

1. 需要完成双账号真机验收，重点覆盖匹配轮询、双方同时交卷、判题延迟、举报结束和跨账号书信未读数一致性；单账号模拟器与真实本地 API 的基础联调已经通过。
2. 当前未读数会在进入主要页面时同步，但没有系统推送；若产品要求后台实时提醒，需要补 FCM 等推送通道。
