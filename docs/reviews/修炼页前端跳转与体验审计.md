# “修炼”模块前端跳转与体验审计

> 审计日期：2026-09-11  
> 审计范围：当前 `feature/creation-contest-demo` 分支的 Android Debug 应用（包名 `com.jueqiao.jianghu`）  
> 对照文档：`文档/机巧江湖_修炼页策划书.docx`  
> 审计原则：以小学高年级至初中用户为中心；优先简化现有入口、文案与跳转，不新增繁杂按钮。

## 1. 执行摘要

本轮已完成代码静态检查、正确 Debug 包安装核验、核心路线逐项实机点击、三本可达秘籍内容走查，以及小屏、大字体、异形屏、页面/系统返回、前后台切换、快速重复点击、触控边缘、系统动画关闭和离线场景验证。共记录 47 项功能/边界场景，发现 **1 项 P0、10 项 P1、9 项 P2、1 项 P3**。

当前“修炼”模块已经具备较完整的视觉场景和部分内容素材，但核心体验更接近“隐藏热区驱动的静态画面演示”，还不能稳定完成策划书要求的“漫画回顾 → 预测 → 试炼 → 得秘籍 → 创作迁移”闭环。优先级最高的不是新增按钮，而是让现有书本、山峰、气泡和题目承担清晰、唯一、可返回的动作。

结论：**当前版本不适合中小学生独立完成修炼任务**。它没有羞辱、倒计时、排行榜或强制签到等焦虑设计，这是可保留的优点；但入口含义、隐藏热区、自动判对和返回循环会迫使学生依赖成人试错。完成 P0/P1 收敛前，建议按“功能演示”而非“可独立学习”验收。

### 已确认的高风险偏差

1. **进入“修炼”后没有直接到达“悟书环”核心内容。** 当前先进入一张引导场景，必须全屏点击显示气泡、再次点击关闭、等待入场动画，再点击一次“修炼”装饰入口，才进入 `Gunlun1`。这与策划书“首页点击修炼进入悟书环”“不要让用户感觉要连续点两次修炼”的要求直接冲突。
2. **首页与修炼页的“问道”互相跳转。** 首页“问道”直接进入 Xiulian，Xiulian 的“问道”又 `navigate(Home1)`；两边都没有提问、目标招式或后山推荐，并会把对方页面压入返回栈。
3. **同一概念存在两套路线和命名。** `Shilian/Houshan1→Houshan2→Houshan3` 与 `Houshan/Learning→Learning2→Learning3/4` 都从“悟书环”附近进入，却分别使用“后山、试炼、修炼、学习”等词，儿童难以建立稳定心智模型。
4. **`Routes.Learning3` 在导航图中重复注册。** 同一路由出现两次，属于明确的路由维护缺陷，可能让后续修改落到错误分支。
5. **弱网会放大入口阻断。** 飞行模式下，无论冷启动还是已登录首页内触发刷新，应用都会退到登录页，没有“网络不可用/重试”提示；网络恢复后重新启动可恢复首页，但修炼在断网期间完全不可达。
6. **顶部部分关键触控区域不足 48dp。** 实机语义边界显示“问道、修为、书信”三个工具约 36×48dp；修炼页返回、修为弹层关闭及弹层内两个文字入口实测均达到约 48dp 高，后者不应被误报。

## 3. 策划书基准（用于判定，不等同于当前实现）

- “修炼”是一级入口，内部并列“悟书环”和“后山问道”，不应再引入独立的三级书架心智。
- 首页点击“修炼”应直接进入“悟书环”，并优先呈现“现在最值得复习什么”。
- 学习闭环应为：漫画回顾 → 预测 → 试炼 → 获得秘籍 → 创作迁移。
- 秘籍包含“未闻、偶得、习得、悟得、传习”五态；“待温习”只是临时标记，不应降级。
- 秘籍详情应尽量在当前场景弹卡呈现，包含“漫画回顾、这一招讲什么、再试一次、把它用起来”。
- “未闻”内容不应打开空白详情，应引导“前往后山”或“换一招看看”。
- 关键触控区域不小于 48dp；正文不小于 14sp、核心标签不小于 15sp；支持减少动态效果。
- 只记录必要学习证据，不以单一等级或百分比代替成长说明。

## 4. 实际跳转地图

```text
首页 Home1
├─ 顶部“问道” → Xiulian（错误复用修炼入口；系统返回 Home1）
└─ 修炼 → Xiulian（引导场景）
   ├─ 第1次全屏点击 → 显示说明气泡
   ├─ 第2次全屏点击 → 隐藏气泡并播放入场动画
   ├─ 修炼装饰按钮 → Gunlun1（当前实现中的“悟书环”入口）
   │  ├─ 说明气泡 → Gunlun2 → Gunlun3 → … → Gunlun15
   │  ├─ 后山 → Shilian/Houshan1 → Shilian2/Houshan2 → Shilian3/Houshan3 → Unfinished → Gunlun1
   │  └─ 修炼 → Houshan/Learning → Learning2
   │     ├─ Learning3（NavHost 重复声明）→ PendingUnlock → Gunlun1 → 系统返回 PendingUnlock（循环）
   │     └─ Learning4
   ├─ 问道 → 新 Home1 → 系统返回 Xiulian（与首页“问道”形成互跳）
   ├─ 修为 → ProgressModal（页内弹层）
   │  ├─ 每日问题 → 两层全屏气泡 → Xiulian
   │  └─ 查看行囊 → Luggage → 关闭回 Xiulian
   ├─ 书信 → 大会书信或挑战书信
   └─ 设置 → Settings

Gunlun6  → Volume1 → Volume1Part2 → … → Volume1Part14 → 新 Gunlun6 → 系统返回 Part14（循环）
Gunlun7  → Volume3Part1 → 仅系统返回 Gunlun7（单页死端）
Gunlun10 → Volume2Part1 → … → Volume2Part15 → 新 Gunlun10 → 系统返回 Part15（循环）

不可达的策划链：
Xiulian/秘籍详情 -X→ 作品创作 -X→ 回到原修炼上下文
Xiulian             -X→ 大会     -X→ 传习状态
首页问道            -X→ 携带目标招式的后山节点
```

> 注：当前代码中的 `Gunlun*`、`Houshan*`、`Learning*` 命名与界面文案不一致，以上同时标出路由名和用户可见概念，避免把代码命名误当成产品结构。

## 6. 问题清单

> 优先级定义：P0 阻断/数据风险；P1 核心任务不可用或路径严重错误；P2 明显影响理解、操作或稳定性；P3 一般一致性与体验问题。

### P0

#### XL-012 核心学习闭环无法真实完成

- **复现路径**：Gunlun1 → 后山 → Houshan1 说明气泡 → Houshan2/Houshan3；或 Gunlun1 → 修炼 → Learning1 → Learning2 → 尝试回答。
- **实际**：后山四座山全部不可选，后续只是无提示的整屏幻灯片，没有题目、预测、输入、反馈、结果或秘籍状态变化；另一条学习路线没有输入却自动判定正确、发放残页，且无法回悟书环验证真实状态，更没有创作迁移。
- **预期**：至少一条路线应真实完成“漫画回顾 → 预测 → 试炼 → 得秘籍 → 返回悟书环 → 创作迁移”，每步能退出、重试并保存可验证证据。
- **影响**：学生无法完成本模块的核心任务，也无法理解“修炼”与成长的关系。自动判对会形成错误学习反馈，静态幻灯片又让儿童误以为自己没点对。
- **建议（不新增按钮）**：先选择现有两条路线中的一条作为唯一主线；让现有山峰/题目承载选择和输入，提交后再复用现有结果页，完成时回写现有行囊五态。未接通前不要展示“回答正确/获得”结果。
- **状态**：两条可达学习路线均完整走查，确认当前无法真实完成核心学习闭环。

### P1

#### XL-001 进入修炼需经历重复且不可预期的点击

- **复现路径**：首页 → 修炼 → 点击任意处显示气泡 → 再点任意处关闭 → 等待 → 再点“修炼”。
- **实际**：核心内容前至少三次点击，其中一级入口“修炼”和场景内“修炼”名称重复。
- **预期**：首页“修炼”一次进入可操作悟书环；首次说明不应再制造第二个同名入口。
- **影响**：儿童会以为第一次点击没有进入，或不知道气泡为何消失后仍需再找一次“修炼”；每次重新组合页面时引导状态还会从头开始。
- **依据**：策划书明确首页“修炼”直接进入悟书环，且命名原则要求避免“连续点两次修炼”的感觉。
- **建议（不新增按钮）**：首次使用保留一次可跳过说明；已看过的用户直接显示可操作的悟书环。复用现有气泡或点击场景继续，不再保留第二个同名“修炼”入口。
- **状态**：代码与实机均确认。实机还确认从 Gunlun1 返回时引导状态重置，重复成本会在同一次使用中反复出现。

#### XL-002 首页与修炼页的“问道”互相跳转，却都没有问道功能

- **复现路径**：首页顶部“问道”→ Xiulian；Xiulian 顶部“问道”→ 新 Home1。
- **实际**：首页“问道”复用 `onOpenXiulian`；Xiulian“问道”调用 `navigate(Routes.Home1)`。两者互相压栈，但都没有问题输入、目标招式或后山推荐。
- **预期**：两个“问道”入口共享同一提问/目标推荐方法，并能携带目标进入后山。
- **影响**：学生按“问道”期望提问，却在首页与修炼之间来回；系统返回会回到刚才页面，像陷入循环，且无法理解“问道”和“修炼”的区别。
- **建议（不新增按钮）**：两个位置复用同一个真正的问道方法，接到产品已定义的提问弹层/后山推荐节点；若功能未完成，暂时隐藏或改用现有气泡明确“内容准备中”，不要用互跳页面冒充。
- **状态**：两向跳转和各自系统返回均完成代码与实机确认。

#### XL-003 两套“后山/学习”路径造成概念和路由重复

- **复现路径**：Gunlun1 分别点击“后山”和“修炼”，走到各自终点后比较页面命名、内容和返回。
- **实际**：`Shilian→Houshan1/2/3` 与 `Houshan→Learning1/2/3/4` 并存；Gunlun1 上分别标作“后山”和“修炼”。
- **预期**：悟书环与后山问道各自只有一条可解释主路由，用户可见名称与任务一致。
- **影响**：同一个修炼模块内出现“修炼、试炼、学习、后山”多套名称，且儿童无法从标签预测会看到什么。
- **建议（不新增按钮）**：先确定两条路径分别对应“后山问道”和“秘籍学习”的唯一产品含义；统一用户文案和路由目标。保留一个主入口，用场景内容承载细分动作。
- **状态**：两条路径均已完成实机逐项走查。

#### XL-011 后山页面要求“选一座山峰”，但山峰全部不可点

- **复现路径**：Gunlun1 → 后山 → 逐一点击“识机真决 / 拆招心法 / 万象谱 / 寻径迷踪步”。
- **实际**：四个标签都是静态图文，没有点击语义；逐一实测均停留原页。唯一可继续的是旁边说明气泡。
- **预期**：现有山峰标签本身可点，默认推荐明确，未解锁节点原地说明条件。
- **影响**：这是核心任务阻断。界面明确要求儿童做选择，但可见目标无响应，会被直接理解为程序坏了。
- **建议（不新增按钮）**：让现有山峰标签本身成为至少 48dp 的入口；默认推荐节点沿用现有高亮“炼”标记。未解锁节点点击后在原位说明“先完成上一座山”，不要加新的入口按钮。
- **状态**：代码与实机均确认。

#### XL-013 “尝试回答”没有输入，却自动判定正确并发放残页

- **复现路径**：Gunlun1 → 修炼 → 点击空白卷轴 → 尝试回答。
- **实际**：页面没有输入框、选项、语音或提交动作；“我的回答”只是多行圆点占位，界面立即显示“回答正确”和“获得识机真诀残页×1”。
- **预期**：先记录学生预测/答案，提交后才判断并给出可重试反馈，奖励依据真实完成证据。
- **影响**：学习证据不真实，儿童也无法理解自己做对了什么；与策划书要求的“先预测、再试炼、看清猜测与结果差异”相冲突。
- **建议（不新增按钮）**：把现有“尝试回答”改为真正进入已有预测/作答组件；提交前不显示结果，提交后在同一页复用现有结果卡反馈差异。若作答尚未实现，应标为“内容准备中”并停止发放奖励。
- **状态**：实机确认。

#### XL-014 “查看秘籍”绕过学习并直接宣布获得，两个分支相互矛盾

- **复现路径**：Learning2 → 查看秘籍。
- **实际**：页面只显示秘籍封面和“成功获得秘籍《识机真诀》”，没有秘籍知识内容；不要求尝试回答。另一分支却只发“残页×1”并随后进入“待解锁”。
- **预期**：“查看秘籍”只查看当前可见内容；获得状态由完成试炼的统一规则决定。
- **影响**：用户无法知道完整秘籍究竟何时获得，奖励规则前后冲突；“查看”被实现成“获得”，按钮文字与结果不一致。
- **建议（不新增按钮）**：未获得时把该入口复用为“先看一招/漫画回顾”，只读不发奖励；完成试炼后同一入口显示“查看秘籍”，并打开策划书规定的页内详情卡。
- **状态**：代码与实机均确认。

#### XL-015 “待解锁”入口返回 Gunlun1，系统返回又回待解锁

- **复现路径**：Learning3 → 点击无文案的熊猫插图 → 待解锁 → 前往解锁 → 系统返回。
- **实际**：“前往解锁”只新增一个 Gunlun1 实例；系统返回回到“待解锁”。从 Gunlun1 再走“修炼”又会回到同一学习链。
- **预期**：前往具体解锁任务，返回时回到来源秘籍/悟书环，不重新落回锁定提示。
- **影响**：儿童可能在“待解锁—悟书环—修炼”之间循环，找不到实际解锁任务。
- **建议（不新增按钮）**：让现有“前往解锁”直接指向唯一的具体试炼节点，并用 `popUpTo`/单例导航避免把 Gunlun1 叠加在待解锁页上；返回应回到秘籍/悟书环，而不是回锁定提示。
- **状态**：实机确认。

#### XL-017 悟书环连续页面的可点击对象与文案不一致

- **复现路径**：Gunlun1 说明气泡 → Gunlun2 → 点击熊猫到 Gunlun5。
- **实际**：Gunlun2–4 通过点击打坐熊猫切换书阵，但无操作提示；Gunlun3 明示“需前往后山试炼”，点熊猫却继续下一张书阵。Gunlun5 明示“选一本心仪秘籍”，所有书都不可点，只有说明气泡能进入下一页。
- **预期**：文案提到的书本/后山就是可点击目标；主要动作 3 秒内可被发现。
- **影响**：儿童会按文字去点书或找后山，却得不到反馈；真正的热区是静态人物/气泡，完全依赖试错。
- **建议（不新增按钮）**：书本就是入口，熊猫和气泡只承担说明；对未解锁书复用原地气泡说明，对已解锁书打开同一套详情卡。删除只为切换静态书阵而存在的页面级导航。
- **状态**：代码、实机点击和截图哈希均确认。

#### XL-018 两本秘籍被拆成 14/15 个路由，唯一“下一页”热区是顶部标题

- **复现路径**：Gunlun6 → 《识机真诀》→ 完整 14 页；Gunlun10 → 中央秘籍 → 完整 15 页。
- **实际**：普通标题承担下一页；没有页码、进度、可见返回/关闭或“轻触继续”。系统返回逐张回退；两册末页都会 `navigate` 新 Gunlun 实例，系统返回又回末页。Gunlun7 的《万象谱》则只有一张静态页，无任何页内操作。
- **预期**：同一阅读容器内有可发现的翻页、进度和退出，读完回到原书阵位置且不新增重复实例。
- **影响**：低龄用户几乎无法发现翻页方式，误点系统返回会逐页倒退；29 个独立内容路由造成过深返回栈和两个末页循环，三本秘籍还采用两种不同结束方式。
- **建议（不新增按钮）**：把现有书页整体作为左右滑动/轻触翻页区域，并复用页内返回热区和页码文字；每册使用单一路由维护当前页，读完 `popBackStack()` 回原书阵，不再 `navigate` 新实例；单页秘籍也使用同一阅读容器。
- **状态**：两册共 29 页及《万象谱》单页均完成实机走查。

#### XL-019 网络失败被当成退出登录，修炼完全不可达

- **复现路径**：飞行模式下冷启动；或已登录停留首页时开启飞行模式并等待/进入修炼。
- **实际**：两种路径都会落到登录页，没有“网络不可用”、离线内容或重试提示；日志记录 `ENETUNREACH`。恢复网络并重启后原登录态可恢复，说明并非真实退出账号。
- **预期**：网络失败不改变登录含义，保留已加载场景并提供温和、可恢复的失败反馈。
- **影响**：网络波动时，学生会误以为账号失效或需要重新输入密码，核心学习内容完全中断；在校园、家庭弱网下风险较高。
- **建议（不新增按钮）**：网络失败与认证失效分开处理；保留现有登录态和已加载的修炼场景，用页面内短提示说明“网络开小差了，稍后再试”。现有触发入口再次点击即可重试，不新增长驻按钮。
- **状态**：飞行模式两种路径实机确认，网络设置已恢复。

### P2

#### XL-004 部分关键触控区域低于 48dp

- **复现路径**：在 Xiulian 点击问道/修为/书信的边缘与中心，并读取 UIAutomator 边界。
- **范围**：1080px、density 420 的实机语义边界中，顶部问道/修为/书信约 95×126px（约 36×48dp），设置约 48×48dp。修炼页返回、修为弹层关闭、“每日生活问题推荐”和“详情请查看行囊”入口实测高度约 48dp，符合高度下限，不列为问题。修为语义边界左侧约 1～8px 内侧点击未命中，中心点击稳定打开。
- **预期**：重要入口透明热区至少 48×48dp，且声明边界内稳定命中。
- **影响**：小学用户更容易点不中，异形屏和单手操作下更明显。
- **建议（不新增按钮）**：保持图标视觉尺寸不变，只扩大透明点击热区到至少 48×48dp；避免把相邻四个工具的热区重叠。
- **状态**：代码、实机语义边界和边缘/中心对照点击确认；设置为约 48×48dp，问道/修为/书信约 36×48dp。

#### XL-005 顶部工具标签字号约 10sp，低于策划基准

- **复现路径**：打开 Xiulian，检查顶部四项代码字号并在基线/1.3 倍字体下观察。
- **实际**：`HomeQuickActions` 标签约 10sp；1.3 倍字体未截断，但默认字号仍低于核心标签 15sp 基准。
- **预期**：核心操作标签至少 15sp，并通过间距而非继续缩字适配宽度。
- **影响**：在高密度屏、小屏和系统大字体场景下可读性不稳定。
- **建议**：把核心标签按策划书提升到至少 15sp；若空间不足，优先减少装饰间距或只保留更清晰的短文案，不增加入口。

## 9. 分阶段优化建议

### 立即修复：修正方向感与可用性（不新增按钮）

1. 让首页“修炼”直接落到可操作的悟书环；首次说明作为可跳过的页内气泡。
2. 修正“问道”的目标和返回栈；统一“后山/试炼/学习/修炼”的用户可见命名。
3. 让现有山峰、书本、气泡与题目承担唯一明确动作，先解除“文字要求点击但元素不可点”的核心阻断。
4. 扩大顶部问道/修为/书信透明热区至至少 48×48dp；保留已经达标的返回、设置和弹层入口。
5. 删除重复 `Learning3` 声明，修正 PendingUnlock 和两册末页返回栈，并给关键路由补回退测试。
6. 把网络失败与登录失效分开，保留已登录状态和已加载场景，复用现有入口重试。

### 下一轮优化：用现有场景补齐学习闭环

1. 在悟书环场景中显示唯一的“推荐温习”焦点，不增加一级入口。
2. 让现有推荐气泡直达关联秘籍；把当前 29 个内容路由收敛为单一阅读容器/页内详情卡，复用现有书本和气泡资产。
3. 统一五态和待温习标记，并确保温习不会降级。
4. 把现有“尝试回答”接到真实预测/作答后再给结果；把“把它用起来”接到已有创作入口，避免新建另一套创作按钮。

### 下一轮优化：适配与体验细化

1. 内容驱动修为弹层高度，移除空白占位并允许小高度窗口滚动；详细证据统一到现有行囊。
2. 支持大字体、小屏、安全区和减少动态效果。
3. 用儿童可理解的动作反馈替代等级/百分比堆叠。

### 暂缓：等待产品或测试数据确认

1. 非空秘籍下五态转换、待温习不降级、试炼失败重试和奖励落库，需提供最小可控测试账号/数据后再验收。
2. “把它用起来”携带 `lessonId` 到作品，以及大会评招后形成“传习”，需先确认现有创作/大会状态接口能承载，避免前端自行造第二套规则。
3. 多秘籍旋转/高亮动画应在唯一信息架构和减少动态策略确定后再优化，不应先继续扩充 Gunlun 页面。

### 不建议实施

1. 不新增一级导航、独立藏经阁、传统任务中心、签到、连续学习、排行榜、热度、倒计时或强提醒。
2. 不为解释隐藏手势继续叠加弹窗；应让现有对象可点、文案与动作一致。
3. 不在同一状态并列多个同功能按钮；书本、山峰、气泡各自只承担一个明确主动作。
