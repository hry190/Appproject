# 创作与大会双账号阶段验收记录

执行时间：2026-09-08 至 2026-09-09，Asia/Shanghai。

本阶段结论：创作版本与大会评招之间的主要接口链路已验证，两个账号也在 Android 模拟器内完成了评语、采纳、修订、登记和通知查收。此次结果支持这条具体链路通过开发环境验收，不能据此认定整个后端、完整学习路线或生产环境已交付。

## 本轮实际修复

1. **未成年人默认发布限制存在绕过。** 原实现只有在 `guardian_controls` 已有记录时才检查未成年人模式，导致同一账号在打开监护设置页前后得到不同权限。现在没有设置记录时按年龄使用默认限制。新增测试分别覆盖未打开设置页和已有默认设置两种情况，均返回 `403 GUARDIAN_VISIBILITY_RESTRICTED`。本轮没有改变已有监护设置的修改权限，监护操作的身份核验仍须单独审查。
2. **登记改进会选到旧版本。** 现在只允许选择同一项目中晚于参会版本的版本；没有新版本时说明原因并提供进入编辑器的入口，确认按钮禁用。
3. **操作失败后缺少可恢复的交互。** 登记改进提交失败时保留原文、展示服务端错误，成功写入并读回后才关闭弹窗；提交期间禁用重复确认。作品详情增加刷新入口和错误重试提示。
4. **作者看到不适用的入口。** 作者不再看到给自己提交评语和向自己申请改造授权的表单。服务端的作者校验继续保留。
5. **重复请求的时间格式不一致。** SQLite 读回评语时丢失时区，造成首次登记与重放响应的 `adopted_at` 格式不同。评语输出时间已统一补齐 UTC，完整响应重放断言通过。

## 接口验收

新增脚本 `services/api/scripts/accept_conference_workflow.py`，从注册账号开始，使用 HTTP 创建项目和 V1，填写工法、推进阶段、提交测试记录、完成学习卡/来源清单/封卷检查、提交发布、调用内部审核接口，再完成另一账号评语、作者采纳、创建 V2、登记改进和导出核对。业务状态没有通过直接插数据库来跳过门槛。

一次完整运行通过 45 次 HTTP 状态检查，并验证：过早提交被拒绝；材料不全被拒绝；审核前另一账号不可见；提交后资料锁定；同一发布请求重放不重复创建；禁止作者自评和他人代作者采纳；V1 不能登记为改进版；V2 创建后项目回到制作阶段，未重新测试不能再次发布；采纳重放不重复发信；公开作品继续指向审核通过的 V1；旧版本未被修改；双方账号导出均包含改进关联。

前置作品为纯文字图层的合成样例，学习卡未关联真实秘籍。本轮证明的是状态和数据流转，不证明作品内容质量、修改是否实质落实建议，也没有完成第 1 页真实学习迁移验收。审核通过由开发内部接口模拟审核人员决策，没有验收真实审核工作台或 Worker 自动消费。

## Android 实际操作

设备：`emulator-5556`，Android 14 / API 34，1080 × 2400。安装包：`com.jueqiao.jianghu.acceptance`，连接本机 8011 端口的独立验收 API。两个账号均为成人测试账号，未影响原应用的账号和创作数据。

实际操作顺序：

1. 评审账号登录，从大会的武会入口打开已审核 V1，选择“建议”并提交评语，页面读回同一条记录。
2. 使用应用内“切换账号”登录作者，点击“作品收到新评语”书信，跳到对应作品。
3. 作者采纳建议。此时尚无 V2，“登记改进”弹窗显示无新版本提示，确认按钮禁用。
4. 从弹窗进入编辑器，拖动画布上的文字图层，保存后页面显示“已保存为 V2”。
5. 返回作品详情，改进版本列表只显示 V2。提交带测试联系方式的说明，后端拒绝，弹窗保留输入并展示错误；修正说明后提交成功，作品详情显示改进记录。
6. 切回评审账号，收到“你的建议已形成新版本”；点击书信进入原作品并看到改进记录。

随后通过接口读回核对：该作品只有一条评语；V2 图层与 V1 确实不同；改进关联指向 V2；改进通知只有一条；公开详情仍指向 V1。未在手机端走建项目、资料填写、发布和审核这些前置步骤，前置数据由上面的 HTTP 流程准备。

## 测试中的失败与处理

端内保存后曾出现一次刷新失败。日志定位到本轮临时验收服务使用 `StaticPool` 共用 SQLite 内存连接，在并发读取时触发结果游标错误；点击重试恢复。这不是一次无错误的操作录像，截图 `35-returned.png` 保留了该失败。

验收服务已改成临时 SQLite 文件及独立连接。重启后重新通过 45 次完整 HTTP 检查，并以 8 个并发线程执行 48 次读取、同时保存一个新版本，全部通过。此检查只验证验收服务的并发回归，不代表生产压测或 PostgreSQL 并发验收；完整手机流程是在切换数据库连接方式之前录制的。

收尾期间工作区发生了其他前端合并，随后 Debug 编译发现修炼页引用的 `img_xiulian_6.png`、`img_xiulian_group128.png` 缺失。本轮从已验证的历史版本 `81fc1c8` 恢复了这两张原始图片，未替换为其他素材。录像绑定下述已保存 APK，合并后的界面改动不包含在这份手机录像中。

## 重现方式

在 `services/api` 目录运行 `.venv/Scripts/python.exe -m scripts.serve_acceptance`，启动临时服务；另一个终端运行 `.venv/Scripts/python.exe -m scripts.accept_conference_workflow --output ../../artifacts/acceptance-rerun.json`。服务停止后测试数据库删除，重跑需重启服务或使用新的测试号码。

手机验收前使用脚本的 `--prepare-only` 准备前置作品，在 `android` 目录运行 `gradlew.bat :app:assembleAcceptance --no-daemon`。测试账号与口令见脚本，均只用于本机开发服务。验收服务使用 noop 短信、内存媒体存储和开发扫描器，不连接真实短信/图像供应商，不启动 Worker。

日常更新 Android Debug 包使用项目根目录的 `infra/install-latest-android.ps1`。脚本会对所有已连接的模拟器卸载 `com.jueqiao.jianghu.acceptance` 和旧的 `com.jueqiao.jianghu`，安装指定 Debug APK，并检查每台设备只剩一个项目包；可先加 `-WhatIf` 预览目标。

收尾时已停止本轮临时验收服务；测试数据库位于系统临时目录，不再被任何进程使用，截图、录像、验收 APK 和 JSON 证据保留。
