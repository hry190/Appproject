## 当前基线

- 数据库迁移：已升级到 `0022_manual_prerequisites`，`alembic check` 通过。
- 后端测试：106 项通过。
- 试炼配置：5 个 ACTIVE 试炼，45 个 DRAFT 试炼；这不等于 5 页完整漫画内容已交付。
- Android：已移除客户端供应商 API 地址和密钥注入通道；Debug 构建和 JVM 单元测试通过。
- 学习纵向切片基础链路：秘籍详情打开时记录幂等阅读事件；详情返回当前 ACTIVE 试炼关联；Android 可从详情进入试炼并提交服务端评分。
- 创作纵向切片推进：封卷阶段可填写迁移理由并按所选秘籍提交幂等迁移证据，服务端审核通过后才允许学习状态晋级。

- 双账号修订入口：作者在大会作品详情可直接进入创作编辑器生成新版本，返回后刷新可采纳版本列表。

## P0 交付门槛

- [ ] 第 1 页完成端内学习闭环：阅读、预测、试炼、解释、迁移证据、创作、发布、评招、修订。
- [ ] 4 条比赛展示路线具备真实内容、试炼规则、迁移任务和录像证据。
- [ ] 50 页内容逐页登记脚本、画面、文字层、审核版本、来源和端内结果。
- [ ] 正式环境使用 HTTPS、PostgreSQL、Redis、MinIO、ClamAV 和 Worker。
- [ ] 生产环境不使用 development image generator 或 development conference judge。
- [ ] 账号删除和匿名化执行 Worker 已完成；仍需定义并验收大会、授权和审计记录保留规则。
- [ ] 内部审核和 Worker 身份完成最小权限隔离。

## 每次复审必须留存

- 提交版本号、数据库迁移版本和构建哈希；
- 测试命令及完整结果；
- 设备、账号类型、前置数据和实际操作录像；
- 失败、重试、断网、返回、刷新和账号切换结果；
- 内容台账中对应页码和版本号。

## 建议执行顺序

1. 先完成第 1 页真实纵向切片。
2. 再完成 4 条主展示路线和 6 条轻量试炼。
3. 再批量补齐其余内容和审核台账。
4. 最后进行双账号大会闭环、生产依赖联调和签名 Release 验收。
