### 踩坑四条(值得记)

1. **统计为 0 时,先怀疑路径,别相信结论。** 迁移脚本第一版把仓库根算成了脚本所在目录(`%TEMP%`),
   于是"替换 0 处 / 残余 0 个"—— 看着像"已经干净了",其实一个文件都没扫到。
2. **幂等判断要看「同一行」,不要看固定长度的窗口。** 补资源名的脚本用"锚点后 60 字符内出现 `img_` 就跳过",
   而下一行正好是 `painterResource(R.drawable.img_...)` → 两处被误判为"已标注"而漏改,后来手补。
3. ⚠️ **最阴的一条:Python 的 `open(..., "w", newline="")` 把 153 个文件的 CRLF 换成了 LF,
   顺手把项目自带的审计脚本打瞎了。** `scripts/audit-comment-drift.ps1` 用 `-split "`r`n"` 切行 ——
   LF 文件整篇变成"一行",于是它**照样报"0 漂移",但配对从 559 掉到 165**。
   发现靠的是**比对它的覆盖数**,不是看它的结论;已把 153 个文件的行尾改回 CRLF,配对恢复 559。
   > 📌 **教训:"工具报通过"要连它的覆盖数一起看。** 只看结论,就会漏掉"工具已经看不见了"这种失败。
4. **机械替换后要抽读几行。** `Gunlun13/14/15` 三处原写作「从 `D:\图/` 复制为 …」,替换后成了
   「从 设计稿  复制为 …」(双空格、读不通)—— 顺手改成人话「从设计稿导入为 …」。
   清单脚本也踩了一次:放开"设计稿 + 任意尾巴"后,把散文 `Figma 设计稿 412×917 基准,参考 …png`
   当成了素材名(名字从 295 涨到 306,多出来的 11 个磁盘上不存在)→ 加"不含中文标点"的过滤。

### 沉淀(§6)

1. **"不入库"和"丢掉"是两件事。** 撤出仓库用 `git rm --cached` + `.gitignore`:**文件留在本地、历史里也还在**
   (用户明确"历史可以留下")。直接删才是真丢 —— 除非确实不打算再跑。
2. **脚本出库时,先问"它的知识在哪"。** 这次的价值不在那 31 个脚本,而在 README 里的判据与踩坑、
   以及 ONBOARDING 里那几行命令;所以**先把知识搬进 `docs/`,再撤代码** —— 顺序反了就得凭记忆重写。
3. **"整个目录都不入库"比"挑几个留"更好维护。** 挑着留会让人每次都问"这个算不算工具";
   一条 `/scripts/` 说清边界,配套在 `.gitignore` 里写清**为什么**和**怎么取回**,成本最低。
4. **上一轮我判断"环境脚本该留"是错的**(至少与用户口径不同)。教训:**这类"该不该入库"的分界,
   要先问清口径再动手** —— 我按"团队要不要"分类,用户按"是不是我的开发辅助"分类,两把尺子结论相反。
